# 真实战斗阶段实施计划

**目标：** 让阶段球不再从主要阶段直接跳过战斗阶段，并把 OCGCore
`MSG_SELECT_BATTLECMD` 的真实攻击候选接入现有情境式卡牌操作。

## 协议与边界

- `MSG_SELECT_IDLECMD` 的 `to_bp` 必须作为 `can_enter_battle` 暴露。
- 主要阶段的阶段球在允许时提供“进入战斗阶段”和“结束回合”，不替玩家选择。
- `MSG_SELECT_BATTLECMD` 解析可发动效果、可攻击怪兽、进入主要阶段二和结束战斗阶段。
- 首轮只提交 OCGCore 已给出的攻击者或阶段动作；攻击目标等后续决策必须继续由
  消息解析器显式处理，不能自动猜测。
- 所有响应在 `DuelSession` 中按当前待决策快照校验，Godot 不接触原始字节协议。

## 实施步骤

- [x] 为主要阶段能力与 `MSG_SELECT_BATTLECMD` 编写失败的解析器测试。
- [x] 扩展 `PendingAction`，解析战斗动作和阶段能力。
- [x] 为进入战斗阶段、提交攻击和结束战斗阶段增加会话语义接口与生命周期测试。
- [x] 经 `YgoCoreBridge` 把能力和战斗候选暴露给 Godot。
- [x] 扩展阶段确认和场上怪兽情境动作，保持动作索引随快照失效。
- [x] 运行原生测试、Godot 契约测试、无头启动和差异检查。
- [x] 使用 Godot MCP 验证阶段选择、战斗阶段状态和动作显示。
